## B-1 — дедупликация машин без номера — ЗАКРЫТО (коммит `d502e54`)

* было: `getUserCars()` брал ключом `car.licensePlate ?? ''`, поэтому все авто
  без номера схлопывались в одну запись;
* стало: дедуп только по непустому номеру (`lib/utils/database_helper.dart`);
* регресс-тест: `test/database_helper_test.dart` — «Машины без номера не
  схлопываются в одну запись (B-1)»;
* окончательно снимается переходом на UUID (раздел D, офлайн-первый синк).

## A-7 — премиум: серверная проверка чека — код ЗАКРЫТ, деплой за пользователем

Проблема: статус премиума жил в клиентском `prefs`, подделать его мог любой
с root или доступом к бэкапу.

Сделано:

* `lib/services/entitlement_client.dart` — клиент серверной проверки; вердиктом
  считается ТОЛЬКО HTTP 200;
* `PremiumService` (единый источник статуса) при покупке и восстановлении
  подтверждает чек на сервере, при старте сверяет статус; новое свойство
  `serverConfirmed` показывает, подтверждён ли премиум сервером;
* `server/ai_proxy/entitlements.py` — проверка чека в Google Play Developer API
  (разовые покупки и подписки), вердикт пишется в Firestore
  `users/{uid}/entitlements/premium`;
* эндпоинты `POST /v1/entitlement` и `GET /v1/entitlement` в `server/ai_proxy/main.py`;
* правила Firestore менять НЕ пришлось: подколлекция `entitlements` и так
  закрыта (deny-by-default) — клиент не может ни прочитать статус, ни подделать его;
* тесты: `test/entitlement_client_test.dart` (7) и
  `server/ai_proxy/selfcheck_entitlements.py` (17 проверок логики).

Главное правило безопасности реализации: сеть, 5xx, `503 verification_unavailable`
и `404 no_record` премиум НЕ отменяют — иначе платящий пользователь терял бы
доступ из-за обрыва связи. Отменяет статус только вердикт Play «чека нет».

Что осталось внешним действием (как и сам прокси):

1. развернуть прокси на VPS (пункт «хост для AI-прокси»);
2. завести сервисный аккаунт и выдать ему в Play Console доступ к заказам и
   подпискам приложения;
3. прописать `PLAY_PACKAGE_NAME` и `PLAY_SERVICE_ACCOUNT_FILE` (или
   `PLAY_SERVICE_ACCOUNT_JSON`) в `/etc/fuelmaster-ai.env`;
4. `AI_PROXY_URL` в `env.defines.json` включает и AI-совет, и проверку чеков.

Пока сервисный аккаунт не задан, сервер отвечает 503, а приложение работает как
раньше (prefs + события магазина) — регресса нет.

## A-6 — App Check: enforcement намеренно оставлен выключенным (до публикации в Play)

Факты (Firebase App Check API и Cloud Monitoring, 2026-09-13):

| Проверка | Значение |
|---|---|
| `firestore.googleapis.com` | `UNENFORCED` — только сбор метрик (с 2025-08-20) |
| `identitytoolkit.googleapis.com` | `UNENFORCED` (с 2025-08-10) |
| Play Integrity для Android-приложения | настроен: `tokenTtl 3600s`, `minDeviceRecognitionLevel NO_INTEGRITY` |
| debug-токены приложения | не зарегистрировано ни одного |
| трафик за 7 дней | 9 запросов, все `MISSING_UNKNOWN_ORIGIN` — проверенных токенов нет |

Почему включать сейчас нельзя: Play Integrity подтверждает, что APK **установлен
из Google Play**. Приложение ещё не опубликовано, друзья ставят APK напрямую —
для такого APK вердикт будет `UNRECOGNIZED_VERSION`, токен не выдаётся, и после
включения enforcement Firestore и вход по email/паролю отвалятся у всех.
Debug-сборки упадут тоже: их debug-токен в проекте не зарегистрирован.

Код при этом готов: `_activateAppCheck()` в `lib/main.dart` включает App Check
до первого обращения к Firebase (debug-провайдер в debug, Play Integrity в release,
DeviceCheck в iOS).

Порядок включения, когда приложение окажется в Play:

1. опубликовать (достаточно внутреннего тестирования) и поставить сборку из Play;
2. прогнать регистрацию, вход, запись заправки, синк — убедиться, что в
   App Check → Metrics появились `verified` запросы по `app_id`;
3. зарегистрировать debug-токены своих debug-сборок (logcat → строка
   `Firebase App Check debug token` → App Check → Apps → Manage debug tokens);
4. включить enforcement по одному сервису, начиная с Firestore —
   `PATCH https://firebaseappcheck.googleapis.com/v1/projects/fuelmaster-984fb/services/firestore.googleapis.com`
   с телом `{"enforcementMode":"ENFORCED"}` (метод `firebaseappcheck.projects.services.patch`,
   проверено по discovery-документу);
5. через 1–2 дня наблюдения за метриками — `identitytoolkit.googleapis.com`;
6. откат — тот же вызов со `UNENFORCED`: мгновенно и без пересборки приложения.
