# Расширение базы автомобилей: подтверждённые нормы расхода

Дата: 13.09.2026. Статус: план + рабочий инструмент сбора.

## 1. Цель

Довести базу до состояния, в котором **по каждому автомобилю известен источник нормы расхода**,
а по китайским маркам (массовые продажи в РФ и КЗ с 2022 года) норма — не оценка, а
**официально опубликованное значение**.

## 2. Текущее состояние (факты, не оценки)

| Показатель | Значение |
|---|---|
| Строк в `assets/cars.csv` | 11 475 |
| Марок | 141 |
| Строк по китайским маркам | **139 (1,2 % базы)** |
| Haval / Geely / Changan / Chery | 15 / 15 / 11 / 5 |
| Колонки нормы | `baseCityNorm`, `baseHighwayNorm` |
| Признак источника нормы | **отсутствует** |

Проблема не только в объёме. Сейчас в базе **нельзя отличить** норму из АМ-23-р Минтранса
от значения, полученного оценкой по аналогам (k-NN, 30 соседей). Для пользователя,
который считает деньги и сверяется с действующей таблицей, это ключевая разница.
Например, Chery представлен моделями A15 / Fora / Tiggo 1.8–2.4 — это техника 2005–2010 годов,
актуального Tiggo 7 Pro / 8 Pro в базе нет вообще.

## 3. Правовая рамка

**Делаем:** работаем с официально опубликованными государственными и ведомственными
данными, с открытыми API и с открытыми реестрами. Государственные системы для того и
публикуют эти данные, чтобы ими пользовались: нормы расхода — это предмет
обязательной сертификации и публичной отчётности.

**Не делаем и не буду делать:** обход платных подписок и paywall, взлом API и подделку
клиентских подписей, использование утёкших или купленных баз, сбор с сайтов вопреки их
условиям, скачивание чужих БД целиком «нахрапом».

Практическая причина здесь не только юридическая. Число, происхождение которого нельзя
подтвердить, ломает ровно то, ради чего всё делается — **точность расчёта**: пользователь
сверяет результат с таблицей, расхождение в 20 % убивает доверие к приложению. А поскольку
приложение публикуется в Play Console под своим именем, нарушения условий источников и
претензии правообладателей бьют по публикации и по аккаунту. Легальные источники при этом
дают данные **лучше и полнее** — что и подтвердил замер ниже.

## 4. Источники: проверено вживую 13.09.2026

### 4.1 🥇 Главный источник для китайских авто — 中国汽车能源消耗量查询 (МИИТ КНР)

Официальная государственная система Министерства промышленности и информатизации КНР:
`https://yhgscx.miit.gov.cn/fuel-consumption-web/`

Производитель обязан сдать данные по каждому одобренному типу ТС; МИИТ публикует их
ежемесячно. Это **первоисточник**, а не пересказ агрегатора.

Проверено: система отвечает из Казахстана, отдаёт **машиночитаемый JSON**
(`POST /fuel-consumption-center/fuel-consumption-center/fcSearchCtr/…`).
Два реестра:

| Реестр | Что даёт | Проверенный охват |
|---|---|---|
| `queryList` (能耗标识, лёгкие ТС) | город / пригород / смешанный + разбивка по циклу WLTC или NEDC | 23 788 записей по 45 целевым маркам |
| `queryNewList` (新版油耗) | `synthesisFuelConsumption` и др., включая коммерческий транспорт | 33 071 запись всего в реестре |

Состав записи (реальный пример, Haval H9):
`usualName` = 哈弗H9, `vehicleNumber` = CC2030CY60G, `displacement` = 2370 см³,
`transmissionType` = AT, `ratedPower` = 137 кВт, `vehicleType` = 乘用车(M1),
`urbanConditions` = 10,31 / `suburbanConditions` = 7,51 / `comprehensiveConditions` = 8,90,
`workConditionVos` = [{WLTC, 10,31, 7,51, 8,90}], `publicTime` = 2024-06.

**Замер по Haval:** 538 записей, 45 уникальных моделей (H6 — 116 записей, 大狗 — 55, H9 — 45,
神兽 — 29, 酷狗 — 20, F7 — 19, 初恋 — 12 …), у 400 записей есть цикл WLTC, у 136 — NEDC.
Смешанный расход по ним: 4,6 / 7,5 / 10,7 л (мин/среднее/макс).

**Охват по маркам (замер):** Changan 4 676 · Great Wall (вкл. Tank) 3 518 · Foton 3 407 ·
Chery 1 428 · Dongfeng 1 901 · Wuling 1 302 · JAC 1 599 · Jetour 1 357 · Great Wall 牌 1 201 ·
BYD 538 · Haval 538 · GAC (广汽乘用车) 1 338 · Brilliance (华晨) 2 228 · Forthing (东风柳州) 1 256 ·
Roewe 492 · Baojun 416 · NIO 372 · Geely 358 · Ora 351 · XPeng 321 · Soueast 245 · MG 232 ·

Важное наблюдение: часть марок ищется **не по марке, а по производителю** —

### 4.2 Остальные источники

| Источник | Что даёт | Статус |

## 5. Главная сложность: сопоставление названий

Китайская модель и её экспортное имя почти всегда разные:

| В реестре МИИТ | В РФ/КЗ на рынке |
|---|---|
| 哈弗初恋 (Chulian) | Haval Jolion |
| 哈弗大狗 (Dagou) | Haval Dargo |
| 哈弗枭龙 | Haval Xiaolong |
| 瑞虎5x / 瑞虎7 | Omoda 5 / Tiggo 7 Pro |
| 艾瑞泽 | Arrizo |
| 长安CS75 | Changan CS75 Plus |
| 长城炮 | GWM Poer |

Значит нужен **табличный маппинг** «китайское название → торговое имя» с ручной сверкой.
Это самая трудоёмкая часть работы и её нельзя автоматизировать «на глаз» — именно здесь
появляются ошибки, когда пользователь видит норму не от своей машины.

## 6. Схема базы: добавить происхождение нормы

Предлагается расширить `assets/cars.csv` (и таблицу в БД):

| Колонка | Смысл |
|---|---|
| `cityNorm`, `highwayNorm` | как сейчас (переименовать `base*` при миграции) |
| `normSource` | `am23r` / `miit` / `ottc` / `epa` / `manufacturer` / `estimated` |
| `sourceRef` | `vehicleNumber` или номер ОТТС — конкретный документ |
| `testCycle` | `NEDC` / `WLTC` / `EPA` / `Минтранс` |
| `confidence` | `verified` / `cross-checked` / `estimated` |
| `verifiedAt` | дата сверки |

Это то, что превращает «базу цифр» в **подтверждённые данные**: пользователю можно честно
показать «норма производителя, WLTC, проверено 13.09.2026» вместо безликой цифры.
В UI — бейдж: производитель / ведомство / оценка по аналогам.

## 7. Собственные данные — самый сильный актив

Приложение уже считает **фактический** расход по заправкам. После 3–5 заправок это значение
точнее любого паспортного. Схема, законная и без персональных данных:
показывать пользователю его фактический расход рядом с нормой; со согласия и в обезличенном
виде — копить медиану по модели. Со временем это единственная база в стране, где есть
реальный расход китайских авто в условиях РФ/КЗ.

## 8. Проверка и триангуляция

1. MIIT ↔ ОТТС ↔ каталог производителя по одной и той же модели.
2. Расхождение ≤ 10 % → `verified`.
3. 10–20 % → `cross-checked`, в базе среднее, в отчёте факт расхождения.
4. > 20 % → не публиковать норму, оставить `estimated` + пометка.
5. Тест качества данных в CI: норма числовая и в диапазоне 2–60 л, топливо и тип ТС из словаря.

Отдельно: цикл. WLTC системно на 10–15 % выше NEDC, а базовые нормы АМ-23-р — эпохи NEDC.
При подстановке WLTC-значения в поле, которое раньше заполнялось по-другому, нужен
один коэффициент и явная пометка цикла, иначе расчёт «поедет» у всех сразу.

## 9. Фазы

| Фаза | Работа | Объём | Риск |
|---|---|---|---|
| 1 | Прогон полного реестра МИИТ по 45 маркам → локальный массив | ~24 000 записей, несколько часов машинного времени | низкий |
| 2 | Маппинг «китайское название → торговое» для моделей, продающихся в РФ/КЗ | ручная сверка, 300–600 строк | средний, требует внимания |
| 3 | Миграция схемы БД: колонки происхождения + бейджи в UI | код + тесты | средний, есть миграция БД |

Ожидаемый результат: **база 11 475 → ~30 000 строк, из них 15–20 тыс. с официально
подтверждённой нормой**, и у каждой строки известен источник.

## 10. Инструмент

`tools/miit_fetch.py` — законный клиент официальной системы МИИТ:

```bash
python tools/miit_fetch.py --registry queryList --probe                # охват по маркам
python tools/miit_fetch.py --registry queryList --brand 哈弗牌          # одна марка
python tools/miit_fetch.py --registry queryList --producer --brand 长城汽车
python tools/miit_fetch.py --registry queryNewList --brand all          # все марки
```

Особенности: вежливая пауза 1 с между запросами, 4 повтора с нарастающей задержкой,
дозапись в JSONL (можно прерывать и продолжать), без потери исходных полей,
`--pages` и `--max-records` для ограничения прогона.

## 11. Что требуется от пользователя

1. Решение: делать маппинг названий вручную (точнее) или полуавтоматически с ручной сверкой.
2. Нужны ли платные агрегаторы (лицензия) — или ограничиваемся открытыми госбазами.
3. Подтверждение схемы provenance (п. 6) — затрагивает миграцию БД и UI.
